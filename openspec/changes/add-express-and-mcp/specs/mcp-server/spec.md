# Spec Delta

## Purpose

Lets MCP-capable coding agents show terminal UI and collect user answers through tool calls, with Express as the preferred, token-efficient input.

## ADDED Requirements

### Requirement: Stdio server
`a2ui-term mcp` SHALL run an MCP server over stdio and SHALL write nothing to stdout except MCP protocol messages.

#### Scenario: Client lists tools
- **WHEN** an MCP client connects and lists tools
- **THEN** it receives `show_ui`, `ask_user`, `update_data` and `close_ui`

### Requirement: UI input is Express or messages
`show_ui` and `ask_user` SHALL take exactly one of `express` (string) or `messages` (array of A2UI v0.9 messages), and an optional `session`. A call with both or neither SHALL fail with a tool error that explains the rule.

#### Scenario: Both inputs given
- **WHEN** an agent calls `show_ui` with `express` and `messages`
- **THEN** the tool returns an error that says exactly one of them is required

### Requirement: Show UI
`show_ui` SHALL open the session pane when needed, apply the UI, and return `{ "ok": true, "session", "surfaceIds" }`.

#### Scenario: Show a form
- **WHEN** an agent calls `show_ui` with valid Express text for surface `form`
- **THEN** the pane shows the form and the result contains `"surfaceIds": ["form"]`

### Requirement: Ask the user
`ask_user` SHALL apply the UI like `show_ui`, wait for the next user action for at most `timeout_s` seconds (default 300), and return the action with `name`, `surfaceId`, `context` and, when present, `dataModel`. It SHALL return `{ "timeout": true }` on timeout and `{ "closed": true }` when the user closes the pane.

#### Scenario: User confirms
- **WHEN** an agent calls `ask_user` with a confirmation dialog and the user presses `Yes`
- **THEN** the tool result contains the action name of the `Yes` Button

#### Scenario: No answer in time
- **WHEN** an agent calls `ask_user` with `timeout_s: 5` and the user does nothing for 5 seconds
- **THEN** the tool result is `{ "timeout": true }`

### Requirement: Update data
`update_data` SHALL take a `surfaceId`, exactly one of `express` (data assignments only) or `updates` (a list of `{ path, value }`), and an optional `session`, and SHALL apply the data changes to that surface.

#### Scenario: Update progress with Express
- **WHEN** an agent calls `update_data` with `surfaceId: "progress"` and `express: "$/status = \"80%\""`
- **THEN** the pane shows `80%` and the result is `{ "ok": true }`

#### Scenario: Express with components
- **WHEN** an agent calls `update_data` with Express text that defines a component
- **THEN** the tool returns an error that `update_data` accepts data assignments only

### Requirement: Close UI
`close_ui` SHALL stop the session renderer and close its pane when the host supports it, and SHALL return `{ "ok": true }`.

#### Scenario: Close
- **WHEN** an agent calls `close_ui`
- **THEN** the renderer stops and the result is `{ "ok": true }`

### Requirement: Structured errors for the model
Compile and validation errors SHALL be returned as tool errors with the message, the line and column when known, a hint, and for unknown components the list of supported components. The pane SHALL stay unchanged.

#### Scenario: Unknown component
- **WHEN** an agent calls `show_ui` with Express text that uses `Chart`
- **THEN** the tool error names `Chart` and lists the supported components
- **AND** the pane shows what it showed before

### Requirement: Express guide
The server SHALL offer a prompt and a resource named `a2ui_guide` that hold the Express reference for the supported component set, generated by the official A2UI agent SDK. Tool descriptions SHALL prefer `express` and include one short Express example.

#### Scenario: Read the guide
- **WHEN** an MCP client reads the resource `a2ui_guide`
- **THEN** it receives the Express grammar and the signatures of every supported component and of no other component
